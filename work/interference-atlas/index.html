Planning spectrum with a proof attached.

Twenty radio sites, one shared band, and a question with real money behind it: how few channels can carry the traffic without sites drowning each other out? Interference Atlas answers with a graph, a colouring and a bound.

The problem with “just reuse channels”

Every site in a shared band is a potential interferer. Reuse a channel too aggressively and the network becomes interference-limited: signal strength is fine, but nobody can decode it. Reuse it too timidly and you have burned spectrum for nothing.

The honest version of the question is a graph problem. Sites are vertices. Two sites are connected when co-channel leakage at either receiver rises above the noise floor by a protection margin. A valid plan is a proper colouring of that graph — and the number of channels is the number of colours.

The model, not a lookup table

Received power comes from a log-distance path loss with a configurable exponent, plus antenna gain. The noise floor is thermal noise in the channel bandwidth:

atlas/model.pyphysics
# thermal noise: -174 dBm/Hz + 10log10(BW) + NF
noise = -174.0 + 10 * log10(bandwidth_hz) + noise_figure_db

# log-distance path loss around a 25 m reference
pl(d) = pl(25) + 10 * exponent * log10(d / 25)

# an edge exists when leakage clears the protection margin
edge(a, b) = max(rx(a → b), rx(b → a)) - noise >= margin

With a 900 MHz band, 200 kHz channels and a 3.2 exponent, the demo field produces 111 edges across 20 sites — a dense graph, but far from complete. That gap between “everything interferes” and “almost everything” is where planning happens.

Two bounds instead of one guess

DSATUR picks the most constrained vertex first and produces an assignment. It is a heuristic, so on its own the channel count is only an upper bound. The planner therefore also computes a maximum clique with Bron–Kerbosch: every vertex in a clique needs its own channel, so the clique size is a lower bound.

On the demo field the clique is seven sites and DSATUR uses nine channels. The report says exactly that: gap of 2. No pretending the plan is optimal when it has not been proven. This is also why the CLI has a --strict flag that exits non-zero when optimality is unproven — the tool can gate a review pipeline.

The SINR map is computed from the final assignment, including adjacent-channel isolation (30 dB) and out-of-band isolation (70 dB), so the picture reflects the plan rather than an optimistic ideal.

What the plan actually buys

The same twenty sites, evaluated with every transmitter on channel zero, are mostly interference-limited. After planning across nine channels they are noise-limited almost everywhere:

Reuse-1 baseline: great  6.1%  good 20.8% fair 56.5% outage 16.6% mean SINR  6.9 dB

What it does not do

  • No terrain, shadowing or antenna azimuths — sites are omnidirectional in two dimensions.
  • Path loss is deterministic; there is no fading margin or Monte-Carlo reliability layer.
  • The colouring is a heuristic. The gap is reported, not optimised away with an exact solver.
  • One channel width for the whole plan, one adjacent-channel isolation value.
